# AeroForge

**Калкулатор и генератор на RC самолет за 3D печат.**

Репозитория: <https://github.com/engdante/AeroForge>

Даваш теглото на товара (мотори, батерии, камери, серва…), типа на модела и
филамента — приложението изчислява размаха и хордата на крилото, скоростите,
задвижването, стабилността, центъра на тежестта, якостта на спаровете и
колко време/филамент/пари ще струва печатът. Показва и опростен **3D
преглед** на пропорциите. Накрая записва отчет, BOM и JSON с дизайна.

> Версия 0.1 (MVP): **всички изчисления + отчет/BOM + 3D преглед**.
> Геометрия за печат (стени, ребра, STL/DXF) — Фаза 6, виж „Пътна карта“.

---

## 0. Накратко

```bash
git clone https://github.com/engdante/AeroForge.git
cd AeroForge
start.bat              # Windows
./start.sh             # Linux / macOS
```

Скриптовете сами създават `.venv`, инсталират зависимостите от
`app/requirements.txt` и отварят приложението в браузъра.

## 1. Инсталиране

### 1.1 Какво трябва да имаш

| Изискване | Забележка |
|---|---|
| **Python 3.10+** (тествано на 3.12) | единствената външна зависимост е `eel` |
| Браузър (Chrome, Edge, Firefox) | Eel отваря системния браузър като прозорец на приложението |
| ~50 MB диск за `.venv` | плюс място за отчетите |

**Не е нужен:** Node.js, npm, база данни, интернет след инсталацията.
Всичко е локално: Python backend + чист HTML/CSS/JS.

Зависимости (`app/requirements.txt`):

```
eel>=0.18,<1.0      # включва bottle, bottle-websocket, gevent
```

Всички изчисления са на чист Python (`math`, `json`, `csv`) — `numpy` и
`scipy` **не** се изискват.

### 1.2 Windows (10/11)

#### Вариант А — най-бързо

1. Инсталирай Python от <https://www.python.org/downloads/> и **задължително**
   сложи отметка **“Add python.exe to PATH”**.
2. Изтегли репозиторито: `Code → Download ZIP`, разархивирай.
3. Двойно щракване върху **`start.bat`**.

При първо стартиране `start.bat` прави следното:

```
Създавам локална среда .venv ...
Инсталирам зависимости от app\requirements.txt ...
Стартиране на AeroForge ...
```

Следващите стартирания са моментални (средата и пакетите вече са налице).

#### Вариант Б — с git

```bat
git clone https://github.com/engdante/AeroForge.git
cd AeroForge
start.bat
```

#### Вариант В — ръчно (пълен контрол над средата)

```bat
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r app\requirements.txt
.venv\Scripts\python.exe app\server.py
```

С конкретен порт (удобно при диагностика): `start.bat 8080` →
<http://localhost:8080/index.html>.

#### Самостоятелен EXE (по избор)

```bat
build_exe.bat
```

Резултат: `dist\AeroForge\AeroForge.exe` — работи без инсталиран Python
(копира се цялата папка `dist\AeroForge\`).

## 2. Как се работи

| Таб | Какво се задава |
|---|---|
| **Товар** | Само общо тегло **или** списък компоненти (име, категория, брой, грамове, позиция от носа). Може да се добави `n` (максимално натоварване). |
| **Мисия** | Треньор / спорт / 3D / планер / крило без опашка / товарен. Оттук идват пресетите за натоварване на крилото, тяга, разтежение и т.н. |
| **Крило** | Натоварване g/dm², AR, свиване, диаедър, позиция на крилото, профил. Празно поле = „авто“ (стойността се вижда като placeholder). |
| **Опашка** | Обемни коефициенти `V_h`, `V_v`, рамо на опашката, статичен запас. |
| **Мотор** | Клетки на батерията, капацитет, желано време на полет, тяга:тегло, мощност W/kg, диаметър на витлото. |
| **Печат** | Филамент, дюза, периметри, запълване, слой, легло на принтера. |

Всичко се преизчислява автоматично при промяна (≈0.3 s). Бутони горе:

* **✨ Пример** — зарежда готов треньор с реален списък компоненти;
* **⚙ Настройки** — изглед (**шрифт и размер на шрифта**), каталог на
  филаментите (плътности, цени в €, якост, дебит, разпенване) и базови
  стойности за нов дизайн; пази се в `settings.json`. Има „Възстанови начални“;
* **📂 Дизайни** — записани дизайни (`designs\*.json`);
* **💾 Запази** — записва входните данни (резултатът се преизчислява);
* **📤 Отчет** — записва `report.html`, `report.md`, `BOM.csv`, `design.json`.

Долу вляво има статус; **двойно щракване** върху него отваря папката с отчети.

### 3D преглед

В резултатите има блок **„3D преглед“** — опростен модел на самолета,
построен от същите изчислени размери (размах, хорд, диаедър, дължина и
размери на фюзелажа, площи на опашката, избран профил):

* крило с лофт по размаха (трапец, диаедър, леко усукване) и контура на
  избрания профил;
* фюзелаж със заоблен нос и стесняваща се опашна част;
* стабилизатор и кил с изчислените площи `S_h` / `S_v`;
* мотор/спинер за ориентиране на носа;
* размери „размах“ и „дължина“ върху сцената.

Управление: **влачене** завърта, **колелце** мащабира, **двойно щракване**
връща изгледа 3/4, бутони за 3/4 · отгоре · странично · отпред.

Това е **визуализация на пропорциите**, не геометрия за печат — обшивката
е една повърхност без дебелина, без ребра и канали (това е Фаза 6).
Рендерът е собствен (canvas 2D, ортографска проекция + сортиране по
дълбочина), без three.js и без интернет.

### Профили (airfoils)

Каталогът съдържа NACA профили (реални координати по формулите на NACA)
и класически профили (Clark Y, S1223, MH 32, E205, MH 45), за които има
аеродинамични данни, но не и вградени координати. За тях приложението
чертае **приблизителен (схематичен) контур** по дебелината и камерата от
каталога — това е само визуализация, а изчисленията ползват `CL_max`,
`CD_min` и допустимия `Re` диапазон на профила.

Смяната на профила променя `CL_max`, `V_stall`, `Re`, дебелината на
профила (а оттам височината на спаровия пояс и якостта) — но **не** размаха
и площта: те се определят от натоварването на крилото `W/S` и масата.
Ако искаш по-голямо крило, промени `W/S` (таб „Крило“).

## 3. Какво изчислява приложението

Всичко е в `app\core\` — чисти функции без зависимости от UI, покрити с тестове.

### 3.1 Масов бюджет (итеративно решение)
Масата зависи от размерите, а размерите — от масата. Затова се решава
уравнението

```
f(m) = товар + конструкция(m) + оценено оборудване(m) − m = 0
```

чрез **бисекция** (10–20 оценки, ~2 ms). Ако конструкцията расте по-бързо от
подемната сила (например PLA с 2 периметъра), решение **не съществува** —
приложението го казва честно и предлага по-високо натоварване или LW-PLA.

### 3.2 Крило и аеродинамика
| Величина | Формула |
|---|---|
| Площ | `S = m·g / (W/S)` |
| Размах | `b = √(AR·S)` |
| Коренов / върхов хорд | `c_root = 2S/(b(1+λ))`, `c_tip = λ·c_root` |
| MAC | `⅔·c_root·(1+λ+λ²)/(1+λ)` |
| Скорост на загуба на подемна сила | `V_stall = √(2mg/(ρ·S·CL_max))` |
| Число на Рейнолдс | `Re = V·MAC/ν` |
| Корекция на CL_max за Re | под 200k пада до 88% при 50k |
| Поляра | `CD = CD0 + CL²/(π·ARe)` |
| Максимално качество | `L/D = √(π·ARe/CD0)/2` |
| Нужна мощност | `P = D·V/η_prop` |

### 3.3 Задвижване
Статична тяга по momentum theory: `T = (2ρA)^⅓·(FM·P)^⅔` (FM = 0.65).
Изчисляват се: максимална мощност, нужна тяга, диаметър на витлото (~25% от
размаха), обороти (лимит по върхова скорост 0.6 M), `Kv`, ток, ESC (1.25×),
капацитет от желаното време, нужен C-рейтинг, реално време на полет.

### 3.4 Опашка, ЦТ и стабилност
`S_h = V_h·S·MAC/l_h`, `S_v = V_v·S·b/l_v`, дължина на фюзелажа `L = k·b`.
Статичният запас е **положителен, когато ЦТ е пред аеродинамичния център**:

```
SM = (x_AC − x_CG) / MAC,   x_AC = x_LE + 0.25·MAC
```

Приложението не само проверява, но и **изчислява къде да застане батерията**:

```
x_bat = (x_target·m_total − Σ_other(m·x)) / m_bat
```

Ако батерията не може да балансира модела, търси се по-добра позиция на
крилото и се дава препоръка в mm.

### 3.5 Якост
```
M_root = 0.106·n·W·b          (елиптично разпределение, конзола)
M_ult  = M_root · 1.5          (коефициент на сигурност)
h_spar = 0.85 · (t/c) · c_root
A_cap  = M_ult / (h_spar · σ_allow),   σ_allow = σ_t·k_layer/1.5
δ_tip  = 0.64 · (n·W/2) · (b/2)³ / (3·E·I)
```
Ако печатаните капси не стигат, приложението избира **карбонова лента**
(стандартни размери 3×0.5 … 15×1.5 mm) и брой ленти на капс, плюс
съединителна карбонова тръба за сглобяемо крило.

### 3.6 Печат
```
обем = площ_обшивка · (периметри·ширина_екструзия) · (1 + вътрешни_елементи)
маса = обем · ефективна_плътност     (LW-PLA ≈ 0.45 g/cm³)
филамент = обем · фактор_разпенване / (π·(1.75/2)²)
време = обем / дебит + слоеве · 1.5 s
```
Точност ±15–20% спрямо слайсер — достатъчно за избор на филамент и план.

## 4. Проверки (✅ / ℹ️ / ⚠️ / ❌)

Натоварване на крилото спрямо типа · скорост на загуба на подемна сила
(хвърляне от ръка) · число на Рейнолдс · тяга:тегло · мощност W/kg ·
витло спрямо размаха · C-рейтинг на батерията · време на полет ·
статичен запас · място на батерията · маса на конструкцията · площ на
спаровите капси · деформация на върха · минимална стена · време за печат ·
място за батерията във фюзелажа · профил за крило без опашка ·
обемни коефициенти `V_h`/`V_v`.

Всяка проверка има обяснение „защо“ и конкретни числа.

## 5. Отчети и файлове

```
exports\<име на дизайна>\
├─ report.html   — самостоятелен отчет (тъмна тема, може да се праща)
├─ report.md     — същият отчет в Markdown
├─ BOM.csv       — компоненти + печатани части (разделител „;“, UTF-8 BOM)
└─ design.json   — пълният резултат (за външна обработка / Фаза 6)
designs\<име>.json — записаните входни данни на дизайните
settings.json      — потребителски настройки (филаменти, цени, базови стойности)
```

Всички цени в приложението и в отчетите са в **евро (€)**.

Съдържание на отчета: обобщение, товар и маси с разбивка, крило/аеродинамика,
опашка и ЦТ, задвижване, якост, таблица на печатаните части, сравнение на
филаментите, всички проверки и дисклеймър.

проверка след промяна на формулите.

## 8. Ограничения и безопасност

* Моделите са **емпирични** (практика на RC моделизма), не CFD/сертификация.
  Константите са изнесени в `presets.py` и са коментирани.
* Оценката за печат е ±15–20% (зависи от слайсера, охлаждането и ретракциите).
* Формата на фюзелажа и разпределението на масата на конструкцията са
  опростени (дялове по секции) — реалният ЦТ се проверява на модела.
* **Преди първия полет**: провери ЦТ на реален модел, направи статично
  изпитание на крилото (~3× полетното натоварване), ограничи хода на
  кормилата, провери обхвата на радиоапаратурата.

## 9. Пътна карта

**Фаза 6 — геометрия за печат** (следваща):
* обшивка с реална дебелина (стени по периметри), вътрешни ребра и
  спарове, канали за карбонови тръби;
* сегментиране по леглото на принтера + гнезда и щифтове за сглобяване;
* фюзелаж по станции с капак и firewall с тягови ъгли;
* панти за кормила, моторна планка, колесник;
* изход `STL` + `DXF`/`SVG` шаблони за ребра;
* план за печат: ориентация, подпори, дължини на тръбите.

Основата е готова: `core/geometry3d.py` вече строи лофт по сечения, а
`design.json` съдържа всички размери — Фаза 6 добавя дебелина, ребра и
изход към файлове.
